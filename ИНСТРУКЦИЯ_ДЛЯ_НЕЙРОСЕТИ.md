# Инструкция для ИИ: Регламент выполнения студенческих лабораторных работ по веб-разработке

Данная инструкция предназначена для передачи в контекст нейросетей (ChatGPT, Claude, Gemini, DeepSeek и др.) перед постановкой задачи на верстку и разработку студенческих лабораторных работ по HTML/CSS/JS.

---

## 1. Главный принцип: Никакой нейросетевой отсебятины, подсказок и самоотчетов

1. **Категорически запрещены блоки «Особенности реализации» и «Пояснения» на страницах:**
   * ❌ Нельзя добавлять на страницу блоки вроде:
     * *«Особенности реализации: Выпадающий блок подменю .submenu спозиционирован абсолютно...»*
     * *«Горизонтальное меню построено с применением свойства float: left...»*
     * *«Вёрстка выполнена на inline-block без применения Flexbox, Grid и JavaScript»*
   * Студент сдает готовую страницу, а не отчет о проделанной работе. Никаких самоотчетов на странице быть не должно!
2. **Запрещены подсказки для пользователя в скобках:**
   * ❌ Не писать: *(Наведите курсор на пункты меню, чтобы увидеть...)*, *(Кликните сюда, чтобы протестировать...)*.
   * На странице размещается **только сам интерфейс** задания (меню, каталог, статья, таблица).
3. **Запрещены комментарии с капсом и упоминанием методички в коде:**
   * ❌ Не писать в комментариях: `/* ТРЕБОВАНИЕ МЕТОДИЧКИ: Flex и Grid СТРОГО ЗАПРЕЩЕНЫ */`, `/* По образцу из методички */`.
   * Комментарии должны быть обычными студенческими, краткими: `/* Каталог товаров */`, `/* Шапка */`, `/* Меню */`.
4. **Запрещены мета-комментарии о тегах и стилях:**
   * ❌ Нельзя писать в тексте: *«Этот абзац демонстрирует тег h6»*, *«Здесь применен селектор по классу»*.
5. **Запрещены технические вставки «для объёма»:**
   * ❌ Не добавлять примеры терминала (`ping 127.0.0.1`, `tracert`, `ipconfig`).
   * ❌ Не вставлять дампы сетевых пакетов и HTTP-заголовков (`GET /index.html HTTP/1.1`, `Status 200 OK`).
6. **Запрещены монструозные порталы:**
   * ❌ Не создавать в корне проекта искусственные «Главные меню» с карточками на все лабы, если преподаватель этого не просил.

---

## 2. Строгое соответствие уровню темы (не забегать вперёд!)

1. **Для лабораторных работ по базовому HTML (Основы HTML, Таблицы, Списки):**
   * **0% CSS-стилей!** Категорически запрещены теги `<style>`, внешние файлы `.css` и инлайн-стили `style="..."` (за исключением редких случаев, когда сам тег прямо прописан в методичке, например `<col style="background: ...">`).
   * Оформление выполняется **строго классическими атрибутами HTML**: `align`, `bgcolor`, `border`, `cellpadding`, `cellspacing`, `width`, `height`, `<font face="..." color="..." size="...">`, `<b>`, `<i>`, `<u>`.
   * Студент на этом этапе «ещё не знает» CSS. Появление CSS сразу выдаёт нейросеть.
2. **Для лабораторных работ по начальному CSS:**
   * Строго соблюдать запреты методички: если тема посвящена `float` или `inline-block` — **Flexbox (`display: flex`) и CSS Grid (`display: grid`) СТРОГО ЗАПРЕЩЕНЫ**.
   * Никакого JavaScript, если задание не по JS.
   * Использовать только те селекторы и свойства, которые изучаются в конкретной теме.

---

## 3. Стандартизированная и единообразная навигация

1. **Единый шаблон в самом верху `<body>` каждого файла:**
   ```html
   <p><a href="prev.html">&larr; Задание 1</a> | <a href="next.html">Задание 3 &rarr;</a></p>
   <hr>
   ```
   * В первом задании только ссылка вперёд: `<p><a href="task2.html">Задание 2 &rarr;</a></p><hr>`
   * В последнем задании только ссылка назад: `<p><a href="task7.html">&larr; Задание 7</a></p><hr>`
2. **Лаконичный текст ссылок:**
   * Везде строго единообразно: `&larr; Задание N` и `Задание M &rarr;`.
   * Без длинных фраз вроде *«Перейти к выполнению следующего практического упражнения»*.
3. **Именование файлов:**
   * По умолчанию `task1.html`, `task2.html` и т.д., **КРОМЕ** случаев, когда в методичке явно задано имя (например, `index.html`, `images.html`, `lab2_l.html`, `text.html`, `menu.html`, `учебник.html`).

---

## 4. Паспорт студента и персональные данные

1. **Формат авторства:**
   * В шапке файла (в HTML-комментарии):
     ```html
     <!-- Выполнил: студент гр. [НОМЕР_ГРУППЫ] [ФИО], [ФАКУЛЬТЕТ], [КАФЕДРА] -->
     ```
   * Внизу страницы перед `</body>` — скромный неброский футер:
     ```html
     <hr>
     <p align="center">
         <font size="2" color="#666666">
             Выполнил: студент гр. 209 БЗУ Баянов Дияз | Факультет ИИМРТ, Кафедра АСУ
         </font>
     </p>
     ```
2. **Без лишних полей:** Не выдумывать строки вроде *«Количество студентов в группе: 20»*.

---

## 5. Графика, спецсимволы и ссылки

1. **Автономность:** Все картинки должны быть локальными (векторные SVG или файлы из задания). Никаких внешних ссылок из интернета, которые сломаются офлайн.
2. **Пропорции кнопок:** Если методичка требует ссылку-картинку (кнопку), текст не должен наползать на стрелки или иконки. Должны быть комфортные отступы.
3. **Корректные спецсимволы:** В CSS псевдоэлементах (`content: "..."`) стрелки указывать либо прямым символом UTF-8 (`content: " ↓";`), либо через CSS-escape (`content: " \2193";`), не допуская появления кракозябр вроде `□93`.

---

## 6. Чек-лист перед сдачей:
- [ ] На страницах нет блоков «Особенности реализации», «Пояснения», подсказок в скобках.
- [ ] В комментариях нет упоминаний методички и кричащих требований капсом.
- [ ] В HTML-работах нет CSS.
- [ ] В CSS-работах не используются flex/grid, если они запрещены.
- [ ] На каждой странице сверху работает одинаковая лаконичная навигация.
- [ ] Группа и ФИО студента указаны правильно.
